## System Overview

A full-stack SvelteKit application for managing equipment rentals and store sales with real-time inventory tracking, guide management, and shift-based operations. Built with PostgreSQL, Drizzle ORM, and Material Web 3 components.

**Stack**: SvelteKit, TypeScript, PostgreSQL, Drizzle ORM, Material Web
**Deployment**: EC2 systemd service, GitHub Actions auto-deploys on push to `rental-system` (blue-green Docker/Nginx infra in repo but not yet active)
**Architecture**: Server-side rendering with SvelteKit, RESTful API, real-time inventory
**Purpose**: Tablet-optimized point-of-sale and rental management system

## Module Guide

### Database Layer

#### `/src/lib/server/db/index.ts` - Database Client
**Purpose**: Singleton Drizzle ORM client initialization
**Exports**: `db` (configured database instance)
**Dependencies**: PostgreSQL via DATABASE_URL environment variable
**Patterns**: Singleton pattern, server-side only
**Gotchas**: Requires DATABASE_URL at runtime, initialized on import

#### `/src/lib/server/db/schema.ts` - Database Schema
**Purpose**: Complete data model with 13 tables and type definitions
**Size**: 1,714 tokens

**Tables**:
| Table | Purpose |
|-------|---------|
| `operators` | Staff members, passcode authentication |
| `shifts` | Operator work sessions, time tracking |
| `productTypes` | Equipment categories (tracked/generic) |
| `trackedItems` | Individual inventory items with unique codes |
| `guides` | Tour guides with PIN and cooldown |
| `rentals` | Core rental transactions (mixed items) |
| `equipmentBlocks` | Maintenance/reservation blocks |
| `rentalProducts` | Rental product bundles/packages |
| `storeProducts` | Point-of-sale inventory |
| `storeSales` | Store product sales transactions |
| `payments` | Payment records (cash/credit) |
| `actionLog` | Audit trail of all operations |

**Key Relationships**:
- Rentals → Operators (via shift)
- Rentals → Guides (optional guide assignment)
- Rentals/StoreSales → Payments
- TrackedItems → ProductTypes
- EquipmentBlocks → TrackedItems
- All have audit timestamps (createdAt, updatedAt)

**Patterns**: JSONB hybrid (structured + flexible), soft deletes via isActive, indexes on query columns
**Gotchas**: Items JSONB allows flexible structures, pricing is JSONB (no DB validation), guide cooldown calculated app-side

### Core State Management

#### `/src/lib/stores/shift.ts` - Shift Store
**Purpose**: Client-side operator and shift session management
**Exports**: `shiftStore` (singleton)
**State**: `{ operator, shift, isLoggedIn }`
**Methods**:
- `subscribe()` - Standard Svelte store
- `setSession(operator, shift)` - Set without API call
- `login(operator, shift)` - Async login
- `logout()` - API call + clear state
- `updateShift(shift)` - Update shift only

**Patterns**: Custom store with methods, reactive state
**Gotchas**: No persistence, depends on server-side session validation, logout doesn't handle errors

#### `/src/lib/types.ts` - Domain Types
**Purpose**: TypeScript interfaces for business entities
**Exports**: Customer, RentalItem, RentalPricing, ProductPricing, ProductAttributes, ItemAttributes, ShiftSummary
**Patterns**: Interface-based, optional fields, discriminated unions
**Gotchas**: RentalItem conditional fields (code for tracked, quantity for generic), all amounts in cents

#### Core Rental Operations
**POST /api/rentals** - Create rental
- Validates product, customer, items, type
- Checks guide cooldown if required
- Validates item availability
- Updates inventory (marks tracked as rented, decrements generic)
- JSONB items storage for flexibility

**PATCH /api/rentals** - Close rental
- Calculates price (hourly minimum 1hr then round up, fullDay flat rate)
- Returns items to inventory
- Creates payment record
- Updates status to completed

#### Shift Management

- `POST /api/shifts/end` - Calculate summary (rentals count, revenue)
- `POST /api/shifts/close` - Excel export + logout (two sheets: rentals + sales)
- `GET /api/shifts/summary` - Financial summary by payment method
- `POST /api/shifts/logout` - Clear cookie only

#### Store Operations
- `POST /api/store-products` - Create (price in cents)
- `PATCH /api/store-products` - Update quantity/active
- `DELETE /api/store-products` - Remove
- `POST /api/store-sales` - Process sale, decrement quantity

## Data Flow

### Rental Creation Flow
```
1. User selects product
2. Validates product has equipment available
3. Form shows required/optional equipment
4. User selects tracked items (by code) and generic qty
5. Optional: Assign guide (if product requires)
6. POST /api/rentals
   - Validate all items available
   - Check guide cooldown
   - Mark tracked items as rented
   - Decrement generic quantities
   - Create rental record with JSONB items
   - Return rental with price estimate
```

### Rental Closure Flow
```
1. User clicks close on rental
2. CloseRentalModal shows items with condition inputs
3. User selects payment method, adds notes
4. PATCH /api/rentals { action: 'close', conditions, payment, notes }
   - Calculate final price (hourly vs fullDay)
   - Mark tracked items as available
   - Increment generic quantities
   - Create payment record
   - Update rental status to 'completed'
   - Return completed rental
5. UI refreshes, rental moves to previous list
```

### Shift Management Flow
```
1. POST /api/shifts/start (operator ID + passcode)
   - Authenticate operator
   - Check for existing open shift
   - Create new shift if needed
   - Set operatorId cookie
2. User works through shift (create rentals, process sales)
3. POST /api/shifts/end (when ready to check numbers)
   - Calculate rentals count and revenue
   - Calculate store sales total
   - Update shift with summary
4. POST /api/shifts/close (end of shift)
   - Fetch all rentals and sales
   - Generate Excel with two sheets
   - Clear operatorId cookie
   - Download file
```

## Key Business Logic

### Pricing Calculation
```
Hourly Rental:
- Minimum 1 hour charge
- Round up minutes to nearest hour
- Math.ceil(minutes / 60) * hourlyRate

Full Day:
- Flat rate from product pricing

Example:
- 45 min @ $20/hr = 1 hour = $20
- 90 min @ $20/hr = 2 hours = $40
- Full day = $50 (flat)
```

### Guide Cooldown System
- Guides have configurable cooldown periods (minutes)
- Cooldown starts after rental return
- System prevents new rentals during cooldown
- PIN verification allows override
- Real-time calculation shows minutes remaining

### Inventory Management
- **Tracked Items**: Individual items with unique codes, status tracked per item
- **Generic Items**: Quantity-based, available and total tracked separately
- **Equipment Blocks**: Time-based unavailability for maintenance
- Both types can exist in same rental

### Authentication & Authorization
- Passcode-based operator login (4 digits)
- Cookie session storage
- No role-based access (all operators have same permissions)
- Guide PIN verification separate from operator auth

## Gotchas & Important Notes

### Database
- Price amounts stored as integers (cents)
- Items array is JSONB - app must enforce structure
- Pricing object is JSONB - no DB validation
- Guide cooldown calculated app-side, not DB-side
- No enum constraints at DB level (status stored as text)

### Authentication
- Session is cookie-based, not in SvelteKit Locals
- No logout invalidation (cookie alone)
- No password/email authentication (passcode only)
- All operators see all data

### Rental Logic
- Mixed item types in single rental (tracked + generic)
- Pricing calculation happens at closure, not creation
- No inventory reservation - items claimed at rental creation
- Equipment blocks are informational only (not enforced at rental time)

### UI/UX
- Viewport is fixed (no zoom) - accessibility concern
- Material Web components required (@material/web)
- No PWA implementation currently
- Real-time updates not implemented (polling-based)

### Deployment
- Production runs on EC2 as a systemd service (`rental-app`)
- Auto-deployed via GitHub Actions on push to `rental-system`
- Health checks via /health endpoint on port 3000
- Blue-green Docker/Nginx infrastructure exists in repo for future use (not yet active)

## Navigation Guide

### To add a new rental feature:
1. Add database logic to schema if needed
2. Create API endpoint in `/src/routes/api/rentals/`
3. Add form/button to `/src/routes/+page.svelte`
4. Call API endpoint from component
5. Handle response and update UI

### To add a new equipment category:
1. Ensure tracked/generic type in schema
2. Use admin equipment page to create
3. Category appears in rental product builder
4. Equipment available for selection in rental form

### To modify operator authentication:
1. Edit passcode validation in `/api/operators/+server.ts` and `/api/shifts/start/+server.ts`
2. Update login form in `/src/routes/login/+page.svelte`
3. Session management in shift.ts

### To add a new admin section:
1. Create directory under `/src/routes/admin/`
2. Add `+page.svelte` and `+page.server.ts`
3. Add navigation link in `admin/+layout.svelte`
4. Implement CRUD operations via API endpoints

### To modify pricing:
1. Edit price calculation in `/api/rentals/+server.ts`
2. Update product pricing in admin rental-products page
3. Store prices as cents in database

### To deploy:
1. Merge PR or push to `rental-system` branch
2. GitHub Actions triggers ci.yml (checks) and deploy.yml (deployment)
3. deploy.yml SSHs into EC2, pulls code, builds, restarts systemd service
4. Health check verifies app is responding on port 3000
5. Rollback: SSH to server, `git checkout <previous-commit>`, rebuild, restart
