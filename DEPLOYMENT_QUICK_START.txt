================================================================================
DEPLOYMENT STEPS (2 HOURS ACTIVE + 24 HOURS DNS)
================================================================================

STEP 1: Configure Terraform (5 min)
  $ cd terraform
  $ cp terraform.tfvars.example terraform.tfvars
  $ nano terraform.tfvars
    - Set domain_name = "xn--caonpoint-m6a.com"
    - Set strong passwords (16+ chars)
    - Set SSH access CIDR to your IP
    - SAVE (Ctrl+X, Y, Enter)

STEP 2: Validate & Deploy (30 min)
  $ chmod +x setup-validate.sh
  $ ./setup-validate.sh
  $ chmod +x package-lambda.sh
  $ ./package-lambda.sh
  $ terraform init
  $ terraform plan
  $ terraform apply
  ✓ SAVE OUTPUTS:
    - elastic_ip (use for DNS A record)
    - lambda_function_url (copy to CloudFlare worker)
    - asg_name (for manual scaling)

STEP 3: Deploy CloudFlare Worker (15 min)
  $ cd ../cloudflare
  $ nano worker.js
    - Replace CONFIG.WAKEUP_URL with your Lambda URL
    - SAVE
  $ npm install -g wrangler
  $ wrangler login
  $ nano wrangler.toml
    - Set account_id from CloudFlare Dashboard
  $ wrangler deploy
  ✓ Go to CloudFlare Dashboard → Workers → Routes
    - Add route: xn--caonpoint-m6a.com/*
    - Add route: odoo.xn--caonpoint-m6a.com/*

STEP 4: Configure DNS (24 hours)
  Option A: CloudFlare as Primary DNS
    - Namecheap → Domain → Nameservers → Custom DNS
    - Add CloudFlare nameservers
    - CloudFlare Dashboard → DNS → Add A records:
      ✓ @ → Elastic IP (Proxied: Yes)
      ✓ odoo → Elastic IP (Proxied: Yes)
      ✓ origin → Elastic IP (Proxied: No)

  Option B: Keep Route 53
    - AWS Route 53 → Update A records with Elastic IP

STEP 5: First Boot (10 min)
  $ cd ../terraform
  $ aws autoscaling set-desired-capacity \
      --auto-scaling-group-name rental-odoo-asg \
      --desired-capacity 1
  ✓ Wait 5 minutes for instance to boot

STEP 6: Initialize Applications (15 min)
  ✓ Visit: https://xn--caonpoint-m6a.com
    - Should see rental management app
  ✓ Visit: https://odoo.xn--caonpoint-m6a.com
    - Create database with master password

STEP 7: Test Scale-to-Zero (10 min)
  $ aws autoscaling set-desired-capacity \
      --auto-scaling-group-name rental-odoo-asg \
      --desired-capacity 0
  ✓ Wait 2 minutes for shutdown
  ✓ Visit: https://xn--caonpoint-m6a.com
    - Should see "Server Waking Up" message
  ✓ Wait 2-3 minutes
  ✓ Refresh - should be back online

================================================================================
QUICK COMMANDS
================================================================================

Scale up:
  $ aws autoscaling set-desired-capacity --auto-scaling-group-name rental-odoo-asg --desired-capacity 1

Scale down:
  $ aws autoscaling set-desired-capacity --auto-scaling-group-name rental-odoo-asg --desired-capacity 0

Get instance IP (for SSH):
  $ aws ec2 describe-instances --filters 'Name=tag:Name,Values=rental-odoo-server' --query 'Reservations[].Instances[].PublicIpAddress' --output text

SSH to instance:
  $ ssh -i your-key.pem ec2-user@<IP>

Check services (via SSH):
  $ sudo systemctl status postgresql-16
  $ sudo systemctl status rental-app
  $ sudo systemctl status odoo
  $ sudo systemctl status nginx

View logs (via SSH):
  $ sudo journalctl -u rental-app -f
  $ sudo journalctl -u odoo -f
  $ sudo tail -f /var/log/backup.log

List backups:
  $ aws s3 ls s3://rental-odoo-backups-<suffix>/daily/

================================================================================
TROUBLESHOOTING
================================================================================

Instance won't boot:
  $ aws autoscaling describe-scaling-activities --auto-scaling-group-name rental-odoo-asg

Domain not resolving:
  - Wait 24 hours for DNS propagation
  - Verify A records in CloudFlare/Route53
  - Check: nslookup xn--caonpoint-m6a.com

Services won't start:
  - SSH to instance
  - Check: sudo systemctl status <service>
  - View logs: sudo journalctl -u <service> -f

CloudFlare Worker not triggering:
  - Check: worker.js has correct Lambda URL
  - Check: CloudFlare routes are attached
  - Check: Lambda logs in CloudWatch
